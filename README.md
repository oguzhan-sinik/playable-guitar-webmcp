# Playable — Tell Your AI Agent What Song You Want to Learn

No link required. Name a song — your agent researches it on the public web,
the site verifies the evidence and compiles a version that fits your hands,
and you practice it in the browser with real chord diagrams and a synthesized
preview of **exactly what you should play**.

```
User
  ↓  "Teach me Perfect by Ed Sheeran. I'm a beginner."
ChatGPT / browser agent          ← the ONLY agent; the page has no LLM
  ↓  public web research (compact facts, multiple independent sources)
WebMCP                           ← request_song · submit_song_evidence
  ↓
Evidence resolver                ← deterministic: normalizes, dedupes, weights
  ↓
SongBlueprint                    ← key · tempo · meter · harmony · form
  ↓
SongGraph
  ↓
Guitar compiler                  ← player-aware beam search, capo optimization
  ↓
Practice Studio                  ← diagrams · loop · metronome · exact synth
```

The agent never generates tabs and never generates music. It researches and
submits small public facts; a deterministic resolver checks the evidence
instead of trusting the model; the guitar compiler searches playable versions
for that specific player's hands. The same selected arrangement drives the
chords, chord diagrams, capo mapping, difficulty, practice plan, and the
guitar sound the player hears.

**Input modes** — all converge to a `SongGraph` before compilation:

- **Song title + artist** (the hero path — no link, no audio)
- Spotify / YouTube link (identity + research path)
- Permitted direct audio (full MIR analysis)
- Manual musical facts + the seeded legal demo song
- Licensed catalog tracks (Jamendo, download-authorized)

- **Music information retrieval**: multi-provider analysis (essentia, madmom,
  beat-this, all-in-one) with evidence-based consensus for tempo, meter,
  downbeats, sections, and chords → a canonical `SongGraph`.
- **Guitar compiler**: deterministic transformations (capo selection,
  chord-shape optimization, rhythm simplification, tempo adaptation, fingering
  optimization) explored as bounded chains (beam search), Pareto-filtered over
  difficulty/fidelity.
- **Player-aware selection**: a `PlayerProfile` (known chords, barre comfort,
  comfortable tempo, techniques) re-scores every candidate — the compiler
  maximizes musical fidelity *subject to* what this specific player can do.
- **Practice Studio**: chord diagrams, section looping, practice tempo,
  metronome, count-in, and a Karplus–Strong synthesis of the compiled
  arrangement.

> Audio preview is not generated by a music model. It is synthesized directly
> from the exact guitar positions (shape + capo) selected by the
> deterministic compiler. The renderer is an instrument, not a composer.

## WebMCP

Added for **The WebMCP Challenge** (September 2026): the web app registers its
guitar-learning capabilities as browser-native tools via
`document.modelContext.registerTool`, so any compatible browser agent (ChatGPT
in-app browser, Chrome 149+ with WebMCP testing enabled) can discover and
compose them around a musician's goal. No proprietary agent integration — the
agent reasons, the page executes.

Human and agent share ONE state: `set_player_profile`, tempo sliders, section
chips, loop toggles — manual clicks and tool calls move the same controls.

### Agent Research: "If we can't hear it, research it"

Mainstream streaming links identify a song but never expose analyzable audio.
Instead of bypassing protections, the browser agent researches the song across
independent public sources and submits **small structured musical facts** (with
source URLs) into the page. A deterministic evidence-fusion engine normalizes
keys (G# = Ab), converts capo'd guitar shapes into sounding harmony, merges
metrical tempo levels (63/126/189 = one pulse), detects transposition
equivalents, weights sources by claim-specific priors, counts only independent
source families, and reports per-field confidence — or honest conflicts. When
enough independent sources agree, a `RESEARCH_FUSION` SongGraph is built and
fed into the unchanged guitar compiler.

Copyright safeguards: evidence payloads are capped (≤32 chord tokens per
section, no lyrics, no tab bodies, nothing paywalled); oversized submissions
are rejected with `EVIDENCE_TOO_LARGE`. The compiler reports two confidence
axes — arrangement fidelity vs song understanding — and research songs use a
section-relative timing grid labeled `SECTION_ONLY` ("Practice progression",
never invented timestamps).

External-media ingestion additionally requires a request-level human rights
attestation (`rightsConfirmed`) — an agent cannot assert it silently. A
licensed catalog (Jamendo, `JAMENDO_CLIENT_ID`) provides a legal real-audio
path for tracks that explicitly allow download.

### Composable hero flow (NO LINK)

```text
request_song ("Perfect", "Ed Sheeran")
get_song_research_brief          → what's missing + suggested queries
   … the agent researches the public web …
submit_song_evidence             → batched facts, one call per independent source
   … more research; brief re-checked; conflicts investigated …
validate_song_blueprint          → READY / READY_WITH_WARNINGS
resolve_researched_song          → SongBlueprint → SongGraph(RESEARCH_FUSION)
set_player_profile
compare_guitar_levels → compile_guitar_version → get_arrangement_diagnostics
choose_learning_section → create_practice_plan → configure_practice_session
prepare_practice_preview → human presses ▶
```

### The link path (Spotify favorite, no audio needed)

```text
load_song_from_link (Spotify)     → RESEARCHABLE, researchAvailable
begin_song_research               → identity (MusicBrainz) + gaps + queries
   … the agent searches the open web …
submit_song_evidence (key/tempo/chords × independent sources)
get_song_research_status          → conflicts resolved, confidence rises
resolve_researched_song           → SongGraph(RESEARCH_FUSION, SECTION_ONLY)
set_player_profile → compile_guitar_version → practice tools → ▶
```

The compiler returns `constraintsSatisfied: false` with the closest available
version when the player's constraints can't be met — an honest fallback, not a
silent compromise.

### Real registration code

From [`src/webmcp/register-tools.ts`](src/webmcp/register-tools.ts):

```ts
await register({
  name: 'set_player_profile',
  description:
    'Set detailed information about the guitarist’s current abilities and physical/practice preferences. …',
  inputSchema: playerProfileSchema,
  execute: async (input) => {
    // …map the agent's natural-language answer into typed profile input
    const profile = setPlayerProfile(profileInput);
    return { saved: true, knownChords: Object.keys(profile.knownChords), … };
  },
});
```

All 24 tools register under one `AbortController`; `dispose()` aborts the
signal and unregisters them. Browsers without WebMCP render the normal UI
unchanged — manual controls, the link path, and the debug invoker still work.

### Architecture

```
Favorite Song URL
      ↓
MIR / SongGraph            (cached per source)
      ↓
WebMCP Agent  ←→  Player Profile     ← the browser agent is the only agent
      ↓
Guitar Compiler            (deterministic, player-aware selection)
      ↓
Arrangement Search         (beam search over transformation chains)
      ↓
Practice Session           (deterministic steps sized to your minutes)
      ↓
Chord Diagrams + Exact Synth Preview
```

Caches are layered: player-profile changes reuse the song analysis; tempo or
metronome changes reuse the rendered preview (cache key = song + arrangement +
section + tempo + metronome).

## Render Deployment

One web service serves the UI, the API, and the WebMCP page from a single origin.

- **Build command:** `corepack enable && pnpm install --frozen-lockfile && pnpm build`
- **Start command:** `pnpm start`
- **Health check:** `GET /health` → `{"ok":true,"service":"guitar-webmcp"}`
- **Required env vars:** none
- **Optional env vars:**
  - `ALLOW_EXTERNAL_MEDIA_INGEST=false` — YouTube/direct-audio ingestion returns a RESEARCHABLE metadata path instead of processing media (set in `render.yaml`).
  - `GUITAR_DATA_DIR` — data directory (default `.data`); set to `/var/data/guitar` when a Render disk is mounted there.
  - `PORT` / `HOST` — provided by Render; defaults `3847` / `0.0.0.0`.

**Persistent disk:** not required. The filesystem is ephemeral on the free plan — research
sessions and caches reset on redeploy/restart. Mount a disk at `/var/data` and set
`GUITAR_DATA_DIR=/var/data/guitar` to persist; no code changes needed. A fresh instance
boots from an empty data dir (the demo song graph is seeded from `seed/demo-song/`).
